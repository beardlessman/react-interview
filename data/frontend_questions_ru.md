# Экзамен по Frontend

Популярные вопросы с собеседований frontend-разработчика.

---

## HTML и семантика

### Зачем нужны семантические теги HTML5?

Семантические теги (`header`, `nav`, `main`, `article`, `section`, `aside`, `footer`) описывают смысл блока, а не только внешний вид. Это помогает скринридерам, SEO и сопровождению: структура документа читается без CSS. Не семантичный `div` оставляют для чисто оформительских обёрток.

### Чем отличаются `article`, `section`, `aside` и `nav`?

- `article` — самостоятельный фрагмент (пост, карточка новости), который можно вынести из контекста.
- `section` — тематическая группа внутри страницы/статьи; обычно с заголовком.
- `aside` — побочный контент (сайдбар, врезка), связанный с основным, но не центральный.
- `nav` — навигационные ссылки (меню, оглавление).  
На странице один `main`; `header`/`footer` могут быть у страницы и у секций.

### Что такое доступность (a11y) во frontend?

Возможность пользоваться интерфейсом людям с ограничениями зрения, моторики, слуха и т.д. База: семантический HTML, контраст, подписи к полям и картинкам, управление с клавиатуры, предсказуемый фокус. ARIA дополняет HTML, когда нативной семантики не хватает; при правильной разметке ARIA часто не нужна.

### Что такое ARIA roles и когда их использовать?

`role` и атрибуты `aria-*` сообщают вспомогательным технологиям роль и состояние виджета (`role="dialog"`, `aria-expanded`, `aria-label`). Правило: сначала нативный элемент (`button`, `a`, `input`), ARIA — только если кастомный контрол неизбежен. Неверная ARIA хуже, чем её отсутствие.

### Как обеспечить доступность с клавиатуры?

Интерактивные элементы должны быть в tab-порядке и активироваться Enter/Space. Видимый `:focus` / `:focus-visible`, логичный порядок в DOM. `tabindex="0"` — в поток таба; `tabindex="-1"` — программный фокус; положительный `tabindex` почти всегда антипаттерн. Для модалок — ловушка фокуса и возврат фокуса на открывший элемент.

### Как правильно размечать формы?

Каждое поле связывают с `<label for="id">` или оборачивают в `label`. Группы радио/чекбоксов — в `fieldset` + `legend`. Обязательность — `required` и понятный текст ошибки, связанный через `aria-describedby`. Не полагаться только на цвет; валидация Constraint Validation API или своя — с сообщениями, доступными скринридеру.

### Чем `<button>` отличается от `<a>`?

`a` — навигация (URL, возможность открыть в новой вкладке). `button` — действие на странице (submit, открыть модалку, переключить состояние) без смены адреса. Нельзя делать ссылку «кнопкой» через `href="#"` и наоборот: ломаются семантика, SEO и a11y. У кнопки по умолчанию `type="submit"` внутри формы — задавайте `type="button"`, если submit не нужен.

### Какие meta-теги важны для SEO и шаринга?

`title` и `meta name="description"` — сниппет в поиске. `meta name="viewport"` — корректный мобильный рендер. Open Graph / Twitter Card (`og:title`, `og:image`, `og:url`) — превью в соцсетях. Canonical — канонический URL при дублях. Для SPA критичны SSR/пререндер или динамические meta на сервере, иначе краулеры могут видеть пустой shell.

### Зачем `srcset` и `sizes` у `img`?

`srcset` перечисляет варианты картинки с дескрипторами ширины (`400w`) или плотности (`2x`). `sizes` говорит браузеру, какую ширину займёт изображение в вёрстке при разных viewport. Браузер выбирает подходящий файл — меньше трафика на мобилках без потери чёткости на Retina.

### Когда использовать элемент `<picture>`?

Когда нужны разные кропы/форматы, а не только масштаб: art direction (`media` в `<source>`), WebP/AVIF с fallback на JPEG/PNG. Внутри `picture` — один `img` как fallback и для a11y (`alt`). `srcset` на `img` достаточно, если меняется только разрешение одного кадра.

### Зачем нужен атрибут `alt`?

Кратко описывает содержание/функцию изображения для скринридеров и при сбое загрузки. Декоративным картинкам — `alt=""`, чтобы их пропускали. Не дублировать соседний текст и не писать «картинка…». Для сложных схем — развёрнутое описание рядом или через `aria-describedby`.

### Зачем `lang` на `<html>` и что даёт DOCTYPE?

`lang` указывает язык документа: правильное произношение скринридерами, переносы, выбор шрифтов. DOCTYPE (`<!DOCTYPE html>`) включает standards mode; без него браузер может уйти в quirks mode с другой моделью раскладки — баги в CSS «на ровном месте».

### Чем block-элементы отличаются от inline с точки зрения HTML/CSS?

Block (`div`, `p`, `section`) занимает ширину контейнера, начинается с новой строки, принимает width/height/margin по вертикали. Inline (`span`, `a`, `em`) течёт в строке; вертикальные margin/width часто не работают как ожидается. Inline-block — гибрид. В современном CSS это скорее `display`, чем «тип тега», но семантика тега от display не меняется.

## CSS и вёрстка

### Что такое специфичность CSS и как её считать?

Вес селектора: inline-стиль > `#id` > `.class` / атрибуты / псевдоклассы > теги / псевдоэлементы. При равенстве побеждает последнее объявление. `!important` ломает каскад — используют редко. Практика: короткие классы, избегать глубоких цепочек и стилей по id.

### Объясните CSS box model. Чем `content-box` отличается от `border-box`?

Элемент = content + padding + border + margin. При `box-sizing: content-box` width — только content; padding/border увеличивают итоговый размер. При `border-box` width включает content+padding+border — удобнее для сеток. Часто глобально: `*, *::before, *::after { box-sizing: border-box; }`.

### Основные идеи Flexbox?

Одномерная раскладка по главной оси (`flex-direction`). Контейнер: `display: flex`, `justify-content`, `align-items`, `gap`, `flex-wrap`. Элементы: `flex-grow` / `shrink` / `basis` (часто `flex: 1`). Подходит для панелей, навбаров, выравнивания в ряду/колонке. Для двумерных сеток чаще Grid.

### Основные идеи CSS Grid?

Двумерная сетка: строки и колонки (`grid-template-columns/rows`), области (`grid-template-areas`), `gap`, выравнивание `justify/align-items` и `place-content`. Элементы размещают через `grid-column` / `grid-row`. Удобен для макетов страницы; Flex — для компонентов внутри ячеек.

### Когда Flex, а когда Grid?

Flex — поток в одном направлении, «сколько элементов — столько и растянем». Grid — явное 2D-размещение, выравнивание строк и колонок сразу. Часто вместе: Grid на layout страницы, Flex внутри карточек/тулбаров. Нет универсального «только Flex» или «только Grid».

### Виды `position` и типичные сценарии?

- `static` — обычный поток.
- `relative` — сдвиг относительно себя; якорь для absolute-потомков.
- `absolute` — относительно ближайшего positioned-предка; вне обычного потока.
- `fixed` — относительно viewport (с оговорками transform у предков).
- `sticky` — гибрид relative/fixed при прокрутке в пределах родителя.

### Как работают `z-index` и stacking context?

`z-index` сравнивается только внутри одного stacking context. Новый контекст создают, например: positioned + z-index, `opacity < 1`, `transform`, `filter`, `isolation`, flex/grid-дети с z-index. Элемент с большим z-index в «нижнем» контексте не перекроет «верхний» контекст. Отладка: искать, кто создал контекст.

### Что такое БЭМ?

Методология именования: Блок (`button`), Элемент (`button__icon`), Модификатор (`button--primary`). Избегает вложенных селекторов и конфликтов глобальных классов. Минусы: длинные имена, дисциплина команды. Альтернативы/соседи: CSS Modules, scoped CSS, utility-first (Tailwind).

### Чем адаптивная вёрстка отличается от отзывчивой (responsive)?

Responsive — плавная подстройка через fluid-ширины, `%`/`fr`/`minmax`, media/container queries. Adaptive — набор фиксированных layouts под брейкпоинты (часто отдельные шаблоны). На практике смешивают: responsive-база + adaptive-уточнения на ключевых ширинах. Mobile-first: сначала узкий экран, затем `min-width`.

### Чем отличаются `rem`, `em`, `vw`/`vh` и `%`?

- `rem` — от корня (`html`); удобно для типографики и отступов.
- `em` — от шрифта родителя/элемента; накапливается при вложенности.
- `%` — от родителя (для width — от ширины containing block).
- `vw`/`vh` — доля viewport; осторожно с мобильным UI chrome (`dvh`/`svh`).  
Не смешивать без системы (дизайн-токены / шкалы).

### Чем CSS transitions отличаются от animations?

Transition — плавный переход при смене свойства (hover, класс). Animation (`@keyframes`) — многошаговая последовательность, может циклть, не требует смены «конечного» состояния снаружи. Для производительности анимируют `transform` и `opacity`, избегают частых изменений layout-свойств.

### Что такое CSS-переменные (custom properties)?

Свойства вида `--color-bg: #fff` на любом узле, чтение через `var(--color-bg)`. Каскадируются и меняются в runtime (темы, брейкпоинты). В отличие от препроцессорных переменных живут в браузере. Fallback: `var(--x, #ccc)`. Хорошая база для design tokens.

### Что такое Critical CSS?

Минимальный CSS для первого экрана (above-the-fold), который инлайнят или грузят с высоким приоритетом, чтобы ускорить First Paint / LCP. Остальные стили — async/defer. Минусы: усложнение сборки, риск дублирования и FOUC при ошибках. Имеет смысл на лендингах и тяжёлых CSS-бандлах.

### Чем reflow отличается от repaint?

Reflow (layout) — пересчёт геометрии элементов (изменение размеров, шрифта, DOM-структуры). Repaint (paint) — перерисовка пикселей без смены геометрии (цвет, тень). Composite — слои на GPU (`transform`/`opacity`). Reflow дороже; батчить DOM-чтения/записи и не форсировать синхронный layout в циклах.

### Что такое media queries и подход mobile-first?

Media queries подключают стили по условиям (`min-width`, `prefers-color-scheme`, `hover`). Mobile-first: базовые стили для узкого экрана, расширения через `min-width`. Container queries (`@container`) реагируют на размер родителя — удобнее для переиспользуемых компонентов, чем только viewport.

## Браузер и Web API

### Как в общих чертах устроен pipeline рендеринга в браузере?

HTML → DOM, CSS → CSSOM → Render Tree → Layout (геометрия) → Paint → Composite. JS может менять DOM/стили и запускать pipeline заново. Понимание этапов объясняет, почему тяжёлый JS, большие изображения и layout thrashing бьют по производительности.

### Чем отличаются cookie, `localStorage`, `sessionStorage` и IndexedDB?

- Cookie — малый объём, уходят на сервер с запросами (если не `HttpOnly`-only для JS); флаги `Secure`, `SameSite`.
- `localStorage` — строковый ключ-значение, переживает сессию, синхронный API, ~5MB.
- `sessionStorage` — как local, но на вкладку до закрытия.
- IndexedDB — большая структурированная БД в браузере, асинхронно, для офлайна/кэша данных.  
Не хранить токены в XSS-доступном storage без защиты.

### Когда выбирать IndexedDB, а не `localStorage`?

Большие объёмы, индексы, бинарные данные, сложные запросы, работа без блокировки main thread (через async/workers). `localStorage` — простые настройки и крошечные флаги. Для синхронизации с сетью часто поверх IndexedDB строят слои (например, в PWA).

### Что умеет History API?

`pushState` / `replaceState` меняют URL без перезагрузки; `popstate` — назад/вперёд. Основа клиентского роутинга SPA. Нельзя кросс-origin URL. Данные state ограничены клонируемыми объектами. Для полного UX учитывают scroll restoration и синхронизацию с реальным URL при шаринге.

### Для чего нужен IntersectionObserver?

Асинхронно сообщает, когда элемент входит/выходит из viewport (или корня). Типично: lazy-load картинок/блоков, бесконечный скролл, аналитика видимости, запуск анимаций при появлении. Легче и эффективнее, чем слушатель scroll с ручными расчётами `getBoundingClientRect`.

### Чем WebSockets отличаются от Server-Sent Events (SSE)?

WebSocket — двусторонний полный дуплекс поверх одного соединения; хорош для чатов, коллаборации, игр. SSE — односторонний поток сервер→клиент по HTTP, проще reconnection и работа через обычные прокси; подходит для ленты событий/уведомлений. Для редких запросов часто хватает обычного HTTP/polling.

### Что такое Service Worker на высоком уровне?

Скрипт в фоне между страницей и сетью: кэш статики/API, офлайн, push (с разрешениями). Жизненный цикл: install → activate → fetch. Ошибки в SW сложно дебажить и легко «сломать» обновления — нужна стратегия кэша (cache-first / network-first) и версионирование.

### Зачем `requestAnimationFrame`?

Планирует колбэк перед следующим кадром отрисовки (~60fps). Для анимаций и чтения layout перед paint — лучше, чем `setInterval`. Браузер может троттлить в фоне. Часто сочетают с отменой через `cancelAnimationFrame`.

### Что такое Web Workers и зачем они frontend-у?

Отдельные потоки без доступа к DOM: тяжёлые вычисления (парсинг, крипто, обработка данных) не блокируют UI. Обмен через `postMessage` (structured clone). Dedicated / Shared / Service Worker — разные задачи. Не «ускоряют магию», а разгружают main thread.

### Что такое Page Visibility API?

`document.visibilityState` / событие `visibilitychange` показывают, видна ли вкладка. Пауза видео, остановка поллинга, снижение частоты таймеров в фоне — экономия батареи и трафика. Не путать с фокусом окна: вкладка может быть видимой, но без фокуса.

### Зачем `navigator.sendBeacon`?

Надёжная отправка небольших данных аналитики при закрытии/уходе со страницы: браузер ставит запрос в очередь и не блокирует unload так агрессивно, как синхронный XHR. Обычно POST, без чтения ответа. Для критичных бизнес-операций всё же подтверждают на сервере иначе.

### Что такое `matchMedia` и `prefers-reduced-motion`?

`window.matchMedia('(max-width: …)')` — JS-аналог media query с `change`-слушателем. `prefers-reduced-motion: reduce` — пользователь просит меньше анимаций; уважать это (отключать parallax/автоплей) — часть a11y и хорошего UX.

### Чем MutationObserver полезен на практике?

Наблюдает изменения DOM (дети, атрибуты, текст) без постоянного поллинга. Кейсы: интеграции виджетов, реакция на сторонний скрипт, подсветка кода. Не замена нормальному data-driven UI во фреймворке; при злоупотреблении легко получить лишнюю работу на main thread.

## Сеть, производительность, безопасность

### REST vs GraphQL с точки зрения frontend?

REST — ресурсы и HTTP-методы, кэш по URL проще, несколько эндпоинтов под экраны. GraphQL — один endpoint, клиент описывает нужные поля (меньше over/under-fetching), сложнее кэш и обработка ошибок; нужны клиенты (Apollo/urql) или ручной fetch. Выбор — контракт API и команды, не «модность».

### Как браузер и CDN кэшируют статику? Роль `Cache-Control`?

`Cache-Control` (`max-age`, `no-store`, `private`, `immutable`) и валидаторы (`ETag`, `Last-Modified`) решают, брать ли из disk/memory cache. CDN кэширует ближе к пользователю и разгружает origin. Для бандлов с хешем в имени — долгий `max-age` + `immutable`; для HTML часто короткий кэш или revalidate.

### Что такое Core Web Vitals: LCP?

Largest Contentful Paint — время отрисовки крупнейшего видимого контента (часто hero-image или заголовок). Улучшают: оптимизация изображений, приоритет LCP-ресурса (`fetchpriority`, preload), быстрый TTFB, не блокировать рендер тяжёлым CSS/JS.

### Что такое INP?

Interaction to Next Paint — отзывчивость на клик/тап/клавишу: задержка до следующей отрисовки. Бьют длинные задачи на main thread, тяжёлые обработчики, лишние ререндеры. Лечат: разбиение работы, `scheduler`/`requestIdleCallback`, мемоизация с умом, меньше синхронной работы в обработчиках.

### Что такое CLS и как его снижать?

Cumulative Layout Shift — визуальная стабильность. Сдвиги из-за картинок/рекламы/шрифтов без зарезервированного места, поздней вставки баннеров. Фиксы: width/height или aspect-ratio у медиа, скелетоны тех же размеров, `font-display` и стабильные резервы под UI.

### Что такое lazy loading и code splitting с точки зрения бандлера?

Lazy load — отложенная загрузка (картинки `loading="lazy"`, роуты/`import()`). Code splitting — бандлер режет чанки; динамический `import()` создаёт отдельный файл, подгружаемый по требованию. Цель — меньший initial JS и быстрее TTI/INP. Важно не дробить слишком мелко (водопад запросов).

### Что такое XSS и как защищаться на frontend?

Cross-Site Scripting — внедрение чужого JS в страницу. Избегать `innerHTML`/`dangerouslySetInnerHTML` с недоверенными данными, экранировать вывод, использовать Trusted Types где возможно, HttpOnly для session cookie, CSP. Санитизация HTML — осторожно и с проверенными библиотеками.

### Что такое CSRF?

Cross-Site Request Forgery — браузер жертвы сам отправляет cookie на ваш сайт с чужой страницы. Защита: SameSite cookies, CSRF-токены, не использовать cookie-сессии для state-changing API без проверки Origin/Referer, предпочитать Authorization header для SPA+API. GET не должен менять состояние.

### Что такое Content Security Policy (CSP)?

HTTP-заголовок/meta, белый список источников скриптов, стилей, картинок, connect. Снижает ущерб от XSS (`script-src`, запрет inline без nonce/hash). Строгий CSP требует дисциплины сборки (nonce на инлайны). `report-uri`/`report-to` помогают мониторить нарушения.

### Какие CORS-ловушки важны frontend-разработчику?

Браузер режет cross-origin ответ без `Access-Control-Allow-*`. С credentials (`cookies`) нельзя `Allow-Origin: *` — нужен конкретный origin. Preflight (OPTIONS) на «непростые» запросы. Ошибки CORS в DevTools часто маскируют реальный статус; правится на сервере/прокси, не «магией» в fetch.

### Что такое mixed content?

HTTPS-страница запрашивает HTTP-ресурс: браузер блокирует active mixed content (скрипты) и предупреждает о passive (картинки). Ломает иконки/API на проде после перевода на HTTPS. Решение: только HTTPS-URL, HSTS, относительные/`https://` ссылки, проверка сторонних виджетов.

### Чем preload, prefetch и preconnect отличаются?

- `preconnect` / `dns-prefetch` — заранее соединиться с origin.
- `preload` — критичный ресурс текущего экрана (шрифт, LCP-image) с высоким приоритетом.
- `prefetch` — вероятный следующий ресурс с низким приоритетом.  
Ошибки: preload всего подряд раздувает сеть; неиспользуемый preload — предупреждения в Lighthouse.

### Как оптимизировать загрузку шрифтов?

Подмножество глифов, современные форматы (woff2), `font-display: swap/optional`, preload критичного файла, recast self-host vs CDN. Избегать невидимого текста слишком долго (FOIT) и скачков метрик (CLS) — резервировать line-height/метрики или использовать size-adjust.

### Что такое waterfall и как его читать в DevTools?

Цепочка запросов во вкладке Network: длина = длительность, отступ = ожидание/очередь. Ищем блокирующий CSS/JS, поздний LCP, цепочки зависимостей (`import` за `import`). Цель — параллелить критичное, отложить остальное, сократить TTFB и число критических запросов.

## Инструменты, тестирование, архитектура

### Чем Webpack отличается от Vite?

Webpack — зрелый бандлер с огромной экосистемой; dev тоже через бандл (медленнее на больших проектах). Vite в dev отдаёт ESM нативно + esbuild/SWC для пребандла зависимостей (быстрый HMR); прод — Rollup/Rolldown. Vite проще старт; Webpack гибче в легаси-кейсах и кастомных пайплайнах.

### npm vs yarn vs pnpm?

Все ставят пакеты из registry. npm — дефолт Node. Yarn (classic/berry) — альтернативные lockfile/UX. pnpm — content-addressable store и жёсткая структура `node_modules` (нет фантомных зависимостей), экономит диск в монорепо. Важно: один менеджер на репозиторий + lockfile в git.

### Что такое tree shaking?

Удаление неиспользуемого ESM-экспорта при бандлинге. Требует `import`/`export`, side-effects-free пакеты (`sideEffects` в package.json), production mode. CommonJS трясётся хуже. Пишите точечные импорты из больших библиотек, когда пакет это поддерживает.

### Зачем source maps?

Связь минифицированного/транспилированного кода с исходниками в DevTools и error-tracking (Sentry). В проде часто uploading maps на сервис ошибок без публичной раздачи. Без maps стектрейсы на проде почти бесполезны.

### Чем unit, integration и e2e тесты отличаются?

- Unit — чистая функция/хук/модуль в изоляции, быстро.
- Integration — несколько модулей вместе (компонент + роутер/store), Testing Library.
- E2E — реальный браузер и пользовательский сценарий (Playwright/Cypress), медленно и хрупко.  
Пирамида: много unit, меньше integration, мало e2e на критичные флоу.

### Jest и Vitest — в чём разница для frontend?

Jest — де-факто стандарт, богатая экосистема. Vitest — API-совместим с Jest, заточен под Vite (быстрее, нативный ESM). Выбор часто следует за сборщиком. Оба: моки, snapshots (осторожно), coverage. Для DOM — jsdom/happy-dom.

### Принципы Testing Library?

Тестировать как пользователь: роли, текст, label (`getByRole`, `getByLabelText`), не классы и детали реализации. `user-event` вместо низкоуровневых fireEvent где возможно. Избегать теста «снимок всего дерева». Цель — уверенность при рефакторинге UI.

### Cypress vs Playwright?

Оба — e2e в браузере. Playwright — несколько браузеров из коробки, сильная автоматизация, трассировки, удобен в CI. Cypress — отличный DX и time-travel, исторически сильнее в одном браузере за раз (экосистема растёт). Выбор: команда, CI, кросс-браузерные нужды.

### Что важно знать о CI для frontend?

На PR: install по lockfile, lint, typecheck, unit/integration, сборка, иногда e2e и Lighthouse. Кэш `node_modules`/store, артефакты build. Preview-деплои (Vercel/Netlify/Chromatic) ускоряют ревью UI. Красный CI блокирует мерж — держать тесты стабильными.

### Что такое feature flags?

Переключатели функций без редеплоя: по пользователю, проценту, окружению. Позволяют canary/gradual rollout и kill switch. На frontend — конфиг с бэка или сервиса (LaunchDarkly и аналоги); важно не светить секретный код только флагом на клиенте и убирать мёртвые флаги.

### Что такое монорепозиторий коротко?

Один репозиторий с несколькими пакетами/приложениями (apps + shared UI). Инструменты: pnpm workspaces, Nx, Turborepo. Плюсы: атомарные изменения shared-кода, единый CI. Минусы: сложность границ пакетов и время CI без грамотного кэша/affected.

### Что такое микрофронтенды коротко?

Разбиение UI на независимо деплоимые куски (Module Federation, iframes, web components, отдельные SPA на путях). Плюс — автономия команд. Минусы: дублирование зависимостей, согласованность UX/версий, сложность роутинга и общей аутентификации. Имеет смысл при реальной орг. масштабе, не «для галочки».

### Что такое дизайн-система во frontend?

Набор UI-компонентов, токенов (цвет, тип, отступы), правил a11y и документации (Storybook). Цель — единообразие и скорость. Важно версионирование пакета, breaking changes и синхрон с дизайном. Не только «библиотека кнопок», но и процесс принятия паттернов.

### Как выглядит хороший handoff из Figma и оценка задач?

Дизайнер отдаёт спеки: отступы, состояния (hover/disabled/error), брейкпоинты, ассеты. Разработчик уточняет edge cases, a11y, данные с API. Оценка: декомпозиция (вёрстка, логика, тесты, риски), буфер на неизвестность, озвучивание допущений. Лучше диапазон и вопросы, чем одна «уверенная» цифра без анализа.

### Зачем Storybook / визуальные регрессии?

Storybook — изолированные состояния компонентов для разработки и ревью. Визуальные регрессии (Chromatic, Playwright screenshots) ловят случайные CSS-поломки. Не заменяют логические тесты, но закрывают слой «выглядит как задумано» между дизайном и продом.
